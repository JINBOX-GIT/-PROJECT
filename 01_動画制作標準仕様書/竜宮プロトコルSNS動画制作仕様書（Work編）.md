# 第1章　目的・適用範囲

## 1.1 本仕様書の目的

本仕様書は、「竜宮プロトコルSNS動画制作標準仕様書 Ver0.7」に定められた基本原則を前提として、ChatGPT Workを用いた時間指定中間静止画の制作方法、品質基準および運用手順を定義する。

従来のSNS動画制作では、開始静止画を動画生成AIに入力し、人物動作や衣装変化を生成モデルへ委ねる工程が中心であった。

本仕様書では、動画生成に先立って、開始時点と終了時点を制作者が確定し、その間に存在するべき人物・衣装・光・背景の状態を、指定時刻ごとの静止画として設計・生成・検証する。

これにより、動画生成AIに委ねていた時間方向の変化を、制作者がより細かく制御できる制作工程を構築する。

## 1.2 基本思想

本方式の基本思想は、以下のとおりとする。

> **動画の変化を生成AIへ一括して委ねるのではなく、時間軸上の重要な状態を静止画として事前に設計し、制作者が承認する。**

中間静止画は、単なる開始画像と終了画像の平均画像ではない。

各時刻における人物の姿勢、視線、身体動作、衣装、特殊効果、背景およびカメラ状態を設計した、独立した制作管理対象である。

## 1.3 適用範囲

本仕様書は、以下の制作に適用する。

- 光姫をはじめとする竜宮六姫の変身動画
- 光の生物との接触・融合演出
- 衣装の分解・再構築
- 人物の表情・視線・姿勢の連続変化
- カメラワークを伴うシーン
- 魔法・光粒子・発光体などの形成演出
- その他、開始状態と終了状態を指定できるSNS動画

対象動画はInstagram Reels等の縦型短尺動画を基本とする。

ただし、本方式自体は15秒動画に限定しない。

## 1.4 本仕様書の位置付け

文書体系は以下とする。

```text
竜宮プロトコルSNS動画制作標準仕様書 Ver0.7
│

```

本仕様書はWorkを用いた中間静止画制作の固有手順を定義する。

また、人物のIdentity・Geometry・Renderingの詳細定義は、該当するビジュアル制作仕様書を参照する。

# 第2章　Work方式の基本構造

## 2.1 Start / End Frame方式

本方式では、1つのCUTについて、以下の2枚の静止画を基準とする。

| 基準画 | 定義 |
|---|---|
| Start Frame | CUT開始時点の確定静止画 |
| End Frame | CUT終了時点の確定静止画 |

開始時刻をT=0、終了時刻をT=Dとする。

DはCUTの長さを秒で表した値である。

この2枚は原則として無変更で保存する。

中間静止画は、その両端に矛盾しない状態として新規制作する。

## 2.2 中間静止画の定義

中間静止画とは、指定時刻T=tにおけるシーンの状態を表現した画像である。

例えば、10秒間のCUTを1秒間隔で設計する場合は以下となる。

```text
T=0秒   Start Frame（確定）
T=1秒   中間静止画
T=2秒   中間静止画
T=3秒   中間静止画
T=4秒   中間静止画
T=5秒   中間静止画
T=6秒   中間静止画
T=7秒   中間静止画
T=8秒   中間静止画
T=9秒   中間静止画
T=10秒  End Frame（確定）
```

新規生成する画像は9枚であり、全体の管理対象は11枚となる。

## 2.3 時間間隔の指定

中間静止画の間隔は、CUTの演出に応じて設定する。

| 制作条件 | 設計例 |
|---|---|
| 10秒・1秒間隔 | T=1〜9秒、9枚 |
| 10秒・2秒間隔 | T=2、4、6、8秒、4枚 |
| 6秒・2秒間隔 | T=2、4秒、2枚 |
| 6秒・1秒間隔 | T=1〜5秒、5枚 |

これらは時間軸設計例であり、Workの生成能力や動画の滑らかさを保証するものではない。

## 2.4 生成画像と動画フレームの違い

本方式で制作する中間静止画は、連続動画の各フレームを直接生成するものではない。

例えば10秒動画を30fpsで制作する場合、映像には300フレーム相当の時間情報が必要となる。

1秒間隔の11枚は、そのうちの主要時点を指定する基準画像である。

中間静止画の制作完了は、動画制作の完了を意味しない。

# 第3章　制作体制・役割分担

## 3.1 制作者

制作者は、以下を決定する。

- CUTの目的
- 開始画像・終了画像
- CUTの長さ
- 中間静止画の生成間隔
- 重要時刻
- 演出の採否
- 生成画像の承認
- 動画生成への移行可否

最終意思決定権は制作者にある。

## 3.2 Chatty

Chattyは、制作仕様の設計および品質検証を支援する。

- Start / End Frameの比較
- 時間軸設計
- 中間時点の状態定義
- Work依頼プロンプト作成
- Identity・Geometry固定条件の整理
- 生成結果の比較・検証
- 失敗原因の分析
- 再生成条件の整理
- QAレポート作成

Chattyは、制作者の承認なくキャラクターや演出を変更しない。

## 3.3 ChatGPT Work

Workは、承認された制作仕様と入力素材に基づき、次の作業を担当する。

- 指定時刻の静止画生成
- 複数時刻の画像制作
- 生成画像の整理
- 時系列比較
- 品質検査の支援
- 生成履歴の記録
- 成果物の整理

Workによる画像生成は、既存のIdentityやGeometryを完全に維持できることを保証するものではない。

生成結果は必ず検査する。

## 3.4 動画生成・編集工程

承認された中間静止画を動画生成工程へ引き渡す。

動画生成モデルの選択およびモデル固有の設定については、該当する個別仕様書に従う。

最終的な動画編集はCapCut等の編集ツールを利用する。

# 第4章　制作パイプライン

## 4.1 標準制作工程

```text
企画・演出設計
    ↓
CUT構成確定
    ↓
Start Frame確定
    ↓
End Frame確定
    ↓
Identity基準画確認
    ↓
Start / End差分分析
    ↓
時間軸設計
    ↓
重要時刻の決定
    ↓
Work依頼プロンプト作成
    ↓
制作者による生成開始承認
    ↓
重要中間静止画の生成
    ↓
重要中間静止画のQA
    ↓
残りの中間静止画生成
    ↓
全時刻の時系列QA
    ↓
NG画像の再生成
    ↓
中間静止画承認
    ↓
動画生成工程へ引継ぎ
    ↓
動画生成・編集
    ↓
完成動画QA
    ↓
投稿承認
```

## 4.2 Start / End差分分析

生成前に、両端画像の差分を確認する。

| 比較対象 | 確認内容 |
|---|---|
| Identity | 同一人物であるか |
| Facial Geometry | 顔骨格・目鼻口の位置関係 |
| Body Geometry | 頭身・体格・四肢の比率 |
| Pose | 頭・肩・腕・手・脚の状態 |
| Costume | 衣装形状・色・装飾 |
| Hair | 髪型・毛束・流れ |
| Lighting | 光源方向・陰影 |
| Camera | 画角・距離・向き |
| Background | 建築物・床・照明・奥行き |
| Effect | 光粒子・生物・変身状態 |

両端画像の差分がすべて時間経過による自然な変化とは限らない。

人物の顔や体型の差異など、制作上の不一致が疑われる場合は、そのまま補間せず制作者へ報告する。

# 第5章　時間軸設計

## 5.1 時間軸の設計原則

中間静止画の設計では、以下の状態を時間ごとに定義する。

1. 人物の姿勢
2. 顔の向き・視線
3. 手足の位置
4. 衣装の状態
5. 光・特殊効果の状態
6. カメラ位置・画角
7. 背景の状態

単純に開始状態と終了状態を50%ずつ混合する方法は採用しない。

## 5.2 重要時刻の先行設計

全時刻を順番に生成する前に、演出上の重要時刻を決定する。

10秒CUTの場合、T=3秒、5秒、7秒などを先に設計する方法を基本候補とする。

ただし、重要時刻は固定ではない。

演出上の意味に応じて設定する。

## 5.3 重要時刻の例

光の生物が形成されるCUTの場合：

| 時刻 | 状態 |
|---|---|
| T=0 | 光の生物は存在しない |
| T=3 | 光粒子が集まり始める |
| T=5 | 光の骨格原型が形成される |
| T=7 | 半透明な身体が形成される |
| T=10 | 光の生物が完成する |

この表は演出設計例であり、すべてのCUTに適用する固定ルールではない。

## 5.4 重要時刻の承認

重要時刻の静止画は、原則として残りの中間静止画を生成する前に品質検査する。

重要時刻がNGの場合は、後続画像を大量生成する前に修正方針を決定する。

# 第6章　Identity・Geometry・Rendering維持

## 6.1 Identity Lock

人物のIdentityは、基準画および正式ビジュアル仕様書に従う。

特に以下を固定する。

- 顔の輪郭
- 顔の縦横比
- 目・眉・鼻・口の形状と配置
- 年齢印象
- 髪色・髪型
- 装飾の識別要素
- 肌の質感
- キャラクター固有の印象

中間静止画生成を理由とした人物の再デザインは禁止する。

## 6.2 Geometry Lock

人体構造の連続性を維持する。

- 頭部サイズ
- 首の長さ
- 肩幅
- 胴体の長さ
- 腕の長さ
- 肘・手首の関節位置
- 脚の長さ
- 骨盤位置
- 身体の奥行き

特に、腕を動かすCUTでは肩・肘・手首・指先を一体の構造として扱う。

手だけを移動させ、腕の構造を無視してはならない。

## 6.3 Costume Lock

衣装が変化しないCUTでは、衣装形状を固定する。

衣装が変身するCUTでは、変化を許可する範囲を明確に指定する。

衣装の変身演出においても、人物の骨格や体型を変更してはならない。

## 6.4 Rendering Lock

絵画的リアリズムの基本仕様を継承する。

案件で指定された場合は以下を採用する。

- Lens：85mm F1.4
- Lighting：Loop Lighting
- 自然な肌の陰影
- 毛束の立体感
- 衣装の素材感
- 宝飾品の光学的質感
- 背景の自然な奥行き

光の演出を追加する場合も、人物がアニメ調・人形調・プラスチックCG調へ変化しないよう検査する。

# 第7章　Motion Continuity

## 7.1 Motion Continuityの定義

Motion Continuityとは、時間方向に並べた静止画間で、人物の動作が自然につながっている状態をいう。

各画像が単独で美しくても、隣接時刻の動作が不自然であれば、連続動画の基準画像としては不適切である。

## 7.2 検査項目

| 項目 | 検査内容 |
|---|---|
| Head Motion | 頭部の向き・傾き |
| Eye Direction | 視線の連続性 |
| Shoulder Motion | 肩の位置・回転 |
| Arm Motion | 肘・手首の移動 |
| Hand Motion | 指の位置・形状 |
| Body Motion | 胴体の向き・重心 |
| Hair Motion | 髪の流れ |
| Costume Motion | 布の動き |
| Camera Motion | 画角・距離の変化 |
| Effect Motion | 光・粒子の移動 |

## 7.3 動作の飛躍禁止

例えば、次の変化はNG候補となる。

```text
T=2秒：右手が胸元
T=3秒：右手が頭上
T=4秒：右手が胸元へ戻る
```

演出上の理由がない限り、動作の急激な飛躍や逆行を許可しない。

## 7.4 形成状態の逆行禁止

光の生物の形成など、段階的に進行する演出では、状態の逆行を禁止する。

```text
NG例

T=5秒：光の生物が完成
T=6秒：光粒子へ戻る
T=7秒：再び完成
```

ただし、意図的な消滅・再形成を演出として承認した場合はこの限りではない。

# 第8章　Camera Continuity

## 8.1 基本原則

カメラ位置・距離・画角の変化も時間軸上で管理する。

人物のサイズ変化は、カメラワークによるものか、生成時の形状変化によるものかを区別する。

## 8.2 画角変化の検査

以下を比較する。

- 人物の画面占有率
- 頭頂位置
- 身体中心位置
- 背景の柱・アーチ位置
- 吊り照明の位置
- 床の遠近感
- カメラの高さ

## 8.3 人物の縦横比維持

9:16画像を作成する場合、人物の縦方向だけを引き伸ばしてはならない。

構図調整では、背景の拡張、適切なトリミング、カメラ位置の再設計を優先する。

# 第9章　特殊効果・変身演出

## 9.1 特殊効果の時間軸管理

光粒子、光の生物、衣装変身などは、人物とは独立した状態管理対象とする。

人物の動作が正常でも、特殊効果の時間変化が不自然であればNGとする。

## 9.2 光の生物の形成

形成段階は案件ごとに定義する。

基本例：

```text
光粒子発生
    ↓
光粒子の集積
    ↓
輪郭形成
    ↓
内部光構造形成
    ↓
半透明な身体形成
    ↓
光量・色彩の完成
    ↓
完成した光の生物
```

形成順序は固定ではなく、演出に応じて変更できる。

## 9.3 光の骨格表現

光の骨格は、実際の動物の骨を描くことを意味しない。

光の線や粒子によって、生物の内部構造と立体的な輪郭が形成されている表現を指す。

参考画像を使用する場合、参考対象を明示する。

例えば、クリオネの光骨格表現をイルカへ応用する場合、継承するのは光の構造表現であり、クリオネの生物形状ではない。

## 9.4 衣装変身の時間軸管理

衣装変身では、変化する領域と変化しない領域を区別する。

例：

```text
元衣装
    ↓
衣装表面の発光
    ↓
衣装全体の粒子化
    ↓
光のベールによる再構築
    ↓
新衣装の形状形成
    ↓
新衣装の完成
```

衣装の変化を、単純な左右半身の色分けによって表現しない。

左右の衣装が別々の完成状態になる演出は、制作者が明示的に指定した場合を除き採用しない。

## 9.5 光のベール

光のベールは、人物の前面に光線を重ねるだけでは成立しない。

身体の前後を回り込む立体的な構造として設計する。

- 手前を通過する光
- 身体の奥側へ回る光
- 背景との遮蔽関係
- 身体表面への反射
- 光の進行方向

これらの整合性を検査する。

# 第10章　中間静止画生成手順

## 10.1 入力素材

Workへ渡す素材は以下を基本とする。

1. Start Frame
2. End Frame
3. キャラクター基準画
4. 関連ビジュアル仕様書
5. 必要に応じた特殊効果参考画像
6. CUT別時間軸仕様

参考画像には用途を付記する。

## 10.2 入力素材の優先順位

- 人物のIdentity・Geometry：正式なキャラクター基準画
- CUT開始状態：Start Frame
- CUT終了状態：End Frame
- 演出の時間変化：CUT別時間軸仕様
- 特殊効果の表現：指定された参考画像

参照素材間に矛盾がある場合は、勝手に統合せず制作者へ報告する。

## 10.3 生成方式

各中間静止画は、Start FrameとEnd Frameを基準として生成する。

原則として、生成済みの直前時刻画像だけを入力して次時刻を生成する方式を標準としない。

これは、前時刻で発生した顔・身体・衣装の誤差が後続画像へ蓄積することを防ぐためである。

ただし、局所的な修正に限り、承認済みの中間静止画を補助参照として使用することは検討できる。

## 10.4 生成順序

標準候補は以下とする。

```text
Start / End確定
    ↓
重要時刻の生成
    ↓
重要時刻QA
    ↓
残りの時刻生成
    ↓
全時刻QA
```

重要時刻が複数ある場合、先にそれらを制作してから間を補完する。

## 10.5 出力画像の条件

- 1時刻につき単独の静止画
- Instagram Reels向け縦9:16を基本
- 人物の頭身・体型を維持
- 文字・枠・比較パネルを追加しない
- 指定していない装飾を追加しない
- 時刻はファイル名・管理表で識別する

# 第11章　品質検査

## 11.1 QAの目的

生成画像が単独で美しいかだけでなく、CUT全体の連続性を検査する。

## 11.2 QA分類

| 分類 | 検査対象 |
|---|---|
| Identity | 同一人物の維持 |
| Facial Geometry | 顔構造 |
| Body Geometry | 人体構造 |
| Hand Geometry | 手指・関節 |
| Hair | 髪型・毛束 |
| Costume | 衣装・装飾 |
| Rendering | 画風・肌・光 |
| Motion | 動作の連続性 |
| Camera | カメラワーク |
| Background | 空間・建築 |
| Effect | 光・粒子・変身 |
| Timeline | 時間軸上の整合性 |

## 11.3 判定区分

| 判定 | 定義 |
|---|---|
| OK | 検査範囲で明確な不一致が認められない |
| NG | 明確な不一致・破綻がある |
| 要確認 | 判断に必要な資料または検証が不足 |
| 未検査 | まだ検査していない |

「画像生成成功」は「QA合格」と同義ではない。

## 11.4 単独画像QA

各画像について、以下を確認する。

- 顔が基準画から変化していないか
- 人体構造が破綻していないか
- 手指が自然か
- 衣装が指定どおりか
- 背景に不自然な変化がないか
- 特殊効果が指定時刻に適切か

## 11.5 時系列QA

全画像を時刻順に並べて確認する。

特に隣接する2枚を比較する。

```text
T=0 → T=1
T=1 → T=2
T=2 → T=3
...
T=9 → T=10
```

人物、背景、光の生物、衣装の状態が自然に推移しているか検査する。

## 11.6 Contact Sheet

全時刻の画像を一覧表示したContact Sheetを作成する。

Contact Sheetは時系列比較のための補助資料であり、単独画像の詳細検査を代替するものではない。

元画像は変更せず、一覧用の縮小画像を別途作成する。

# 第12章　失敗時の再生成

## 12.1 失敗の分類

主な失敗を以下に分類する。

- Identity Drift
- Facial Geometry Drift
- Body Geometry破綻
- Hand Geometry破綻
- Costume Drift
- Camera Jump
- Background Drift
- Motion Discontinuity
- Effect Discontinuity
- Premature Completion（完成状態の早出し）
- State Regression（状態の逆行）

## 12.2 再生成原則

NG画像をそのまま後続工程へ使用しない。

再生成時は、失敗内容を具体的に記録する。

「もっと自然に」「もっと綺麗に」などの抽象的な指示だけで再生成しない。

## 12.3 原本への復帰

IdentityやGeometryが破綻した場合は、必要に応じてStart / Endの原本と正式基準画へ戻る。

破綻画像を繰り返し編集することで、誤差を拡大させない。

## 12.4 再生成履歴

| 項目 | 内容 |
|---|---|
| CUT | 対象CUT |
| 時刻 | T=○秒 |
| Take | 生成回数 |
| NG内容 | 具体的な不一致 |
| 修正指示 | 変更する条件 |
| 維持条件 | 変更禁止の要素 |
| 結果 | OK／NG／要確認 |
| 採否 | 採用／不採用／保留 |

# 第16章　実制作から得られた知見

## 16.1 光姫・クリオネイルミネーション

本方式の初期適用事例。

開始画像と終了画像を固定し、時間指定によって中間静止画を生成する制作方法を検証した。

この方式により、動画生成前に変化途中の状態を個別に設計・検討できるようになった。

## 16.2 2026年10月28日の10秒間中間静止画実験

記録された実験結果は以下のとおり。

| 項目 | 結果 |
|---|---|
| 動画尺 | 10秒 |
| 入力 | 開始・終了の2枚 |
| 新規生成 | 中間静止画9枚 |
| 生成順 | 3秒・5秒・7秒を先行 |
| 取得結果 | 9枚 |
| 再生成 | 0回 |
| 動画生成 | 未実施 |
| 連続動画としての評価 | 未成立 |

生成画像の取得には成功したが、以下の不連続が確認された。

- 2秒から3秒への手の動きの飛躍
- 5秒での光の生物の完成状態の早出し
- 5秒から6秒への形成状態の逆行
- カメラ距離の不連続
- 背景建築の位置関係の変化
- 衣装・装飾の細部の変動

したがって、時間指定生成は有効な制作手段の候補である一方、時系列の自動的な連続性は保証されない。

## 16.3 イルカイルミネーションへの展開

クリオネで使用した制作方法を、光のイルカとの融合変身演出へ展開した。

主な制作対象は以下である。

- CUT00：光のイルカの誕生
- CUT01：接触・融合開始
- CUT02：融合と衣装変化
- CUT03：完成状態への移行

この展開により、時間軸設計だけでなく、光の生物の形成状態、衣装変化、人物動作をそれぞれ独立して管理する必要性が明確になった。

なお、各CUTの生成結果や動画としての合格状態は、個別のQA記録によって判断する。

## 16.4 確認済み事項と未検証事項

### 確認済み事項

- 開始・終了画像を基準として中間静止画を生成できる
- 1秒単位の時刻指定による画像制作が可能
- 重要時刻を先に制作する工程を構成できる
- 各時刻の生成結果を比較・評価できる
- 時間軸上の不連続をQAで発見できる

### 未検証事項

- 生成した中間静止画から滑らかな動画を安定して制作できるか
- 複数CUT間でIdentityを十分に維持できるか
- 画像枚数と動画品質の最適な関係
- 中間画像を動画生成モデルへ入力する最適方式
- 再生成回数と品質改善の関係
- 動画生成コストの削減効果

未検証事項は確定した制作効果として扱わない。

- 動作の飛躍
- 光の不自然な消滅・出現

- CUT間の接続
- 音楽・効果音との同期
- SNS動画としての演出効果

# 第18章　FlovaAI連携・動画生成運用

## 18.1 FlovaAIの役割と適用範囲

### 18.1.1 本章の目的

本章は、ChatGPT Workで作成・検証・承認された時間指定中間静止画を、FlovaAIの動画生成工程に引き渡し、動画化・品質検査・修正・再生成する固有手順を定義する。

「竜宮プロトコルSNS動画制作標準仕様書 Ver0.7」および本仕様書第1〜17章を前提とし、共通規則は再定義しない。

### 18.1.2 基本原則

```text
制作者・Chatty：企画・演出・時間軸設計
  ↓
ChatGPT Work：Start / End Frameに基づく中間静止画制作
  ↓
静止画QA・制作者承認
  ↓
FlovaAI：生成方式・入力・コストの確認
  ↓
制作者の明示的な生成開始承認
  ↓
動画生成・動画QA・採否判定
  ↓
CapCut等：最終編集・完成動画QA
```

Workは時間軸上の状態を設計・検証し、FlovaAIは承認済み素材から時間方向の動きを生成する。FlovaAIによる人物Identity、衣装、演出意図、Start / End状態の独自変更は禁止する。

### 18.1.3 適用範囲

- Start / End Frameを用いた動画生成
- Workの承認済み中間静止画を基準とする短尺動画
- 複数区間の動画接続
- 光粒子、融合、衣装変身等の連続演出
- 人物の動作・視線・姿勢、カメラ変化

具体的な入力方法は採用モデルの対応機能に依存する。

## 18.4 開始・終了フレームの指定方法

### 18.4.1 Start / End Frameの固定

Workで承認した確定原本を使用する。動画生成モデルによる開始・終了状態の独自再解釈を防ぐため、役割を明示する。

### 18.4.2 生成方式の確認

採用モデルについて、開始・終了画像指定への対応、動画尺、解像度、アスペクト比、画像入力数、Identity維持上の制約、カメラ指定方法、クレジットを確認する。特定モデルの機能を全モデルの標準機能と扱わない。

### 18.4.3 終了状態の評価

End Frameから逸脱した動画は、単に自然な映像であることを理由に合格にしない。人物位置・姿勢、視線・表情、衣装完成状態、特殊効果、背景・カメラ、次CUTとの接続を検査する。

## 18.5 中間静止画を利用した動画分割・生成

### 18.5.1 基本思想

中間静止画は時間軸の基準状態であり、全画像の一括入力を必須としない。採用モデルの機能に応じて短尺区間へ分割する。

### 18.5.2 分割方式の例

```text
CUT01：10秒
Start Frame（T=0）
    ↓ 動画生成区間A
Intermediate Frame（T=5）
    ↓ 動画生成区間B
End Frame（T=10）
```

各区間で開始・終了画像を指定できるモデルの場合に検討可能。生成後に編集で接続する。

### 18.5.3 分割数の判断

動作の複雑度、重要時刻、衣装・特殊効果の変化量、Identity維持難易度、モデルの尺、接続難易度、想定クレジットを考慮する。中間静止画の枚数だけでは決定しない。

### 18.5.4 分割接続の品質検査

接続位置で顔・身体、手指・姿勢、衣装、髪、光粒子の位置と方向、背景、カメラ、動作速度を検査する。不連続がある場合は編集で補正できるか、再生成が必要か判断する。

### 18.6.2 修正指示の構造

```text
# TARGET

# PROBLEM
発生した問題：

# EXPECTED
本来あるべき状態：

# FIX
修正する内容：

# KEEP
変更してはならない内容：

# REFERENCE
使用する承認済み基準画像：

# CONFIRMATION
修正方法：
再生成の必要性：
想定消費クレジット：

# RULE
現段階では再生成しない。修正方針の確認のみ行う。
```

### 18.6.3 問題発生時の切り分け

1. Work基準静止画自体に問題があるか
2. 中間静止画間の時間変化に不連続があるか
3. FlovaAIへの素材・指示に不備があるか
4. 採用モデルの生成結果に問題があるか
5. 編集工程で修正できるか

### 18.6.4 Workへの差し戻し条件

基準画像の構造問題、重要時刻の不適切な姿勢、衣装変化の矛盾、光骨格・融合状態の設計不足、Start / End間の成立しない変化、必要な重要時刻の欠落がある場合はWorkへ差し戻す。

### 18.6.5 FlovaAI側での修正条件

基準静止画が正しいにもかかわらずIdentity Drift、動作・順序・旋回方向の誤り、衣装変化の逆行、カメラ指定の逸脱、終了状態未到達が生じた場合はFlovaAIでの修正・再生成を検討する。

### 18.6.6 編集工程での修正条件

区間の開始終了、接続タイミング、音声・効果音、テロップ、軽微な尺、映像の再構成はCapCut等での補正を優先する。ただしIdentityや重要演出を損なわない。

---

## 18.7 生成結果の品質検査

### 18.7.1 動画QAの位置付け

静止画QAの合格は動画品質を保証しない。動画生成後に別途QAを行う。

### 18.7.2 検査項目

| QA分類 | 検査内容 |
|---|---|
| Identity | 顔・髪・年齢印象・人物同一性 |
| Geometry | 頭身・骨格・体型・手指 |
| Costume | 衣装形状・色・装飾・変化状態 |
| Rendering | 絵画的リアリズム・質感・照明 |
| Motion | 動作の連続性・速度・方向 |
| Effect | 光粒子・融合・分解・再構築 |
| Camera | 画角・倍率・視点・アスペクト比 |
| Timeline | 指定時刻と演出進行 |
| Continuity | 区間・CUT間の接続 |
| Audio | 音楽・効果音・台詞との同期 |

### 18.7.3 判定区分

- **OK**：仕様を満たし採用可能
- **NG**：仕様違反で修正が必要
- **要確認**：制作者判断が必要

### 18.7.4 重要時刻の検査

開始、Work指定の重要時刻、分割接続、終了を重点確認する。必要に応じ動画から検査静止画を抽出し承認画像と比較する。

---

## 18.8 NG判定時の再生成・差し戻し

### 18.8.1 再生成の基本原則

NG発生時は同条件の再生成を繰り返さず、原因・修正方法・改善可能性・想定クレジットを確認する。

### 18.8.2 再生成判断フロー

```text
動画QAでNG
  ↓
問題時刻・内容を特定
  ↓
Work基準画像に問題？
  ├─ YES → Workへ差し戻し → 静止画修正・QA・承認
  └─ NO
       ↓
     後編集で修正可能？
       ├─ YES → CapCut等で修正
       └─ NO → FlovaAIでの修正方式を検討
                    ↓
                 想定クレジット確認
                    ↓
                 制作者の再生成承認
                    ↓
                 再生成・動画QA
```

### 18.8.3 再生成時の管理

元Take、NG内容・時刻、修正・維持対象、変更条件、基準素材、想定・実消費クレジット、結果、採否を記録する。NG素材を正式基準として無条件に再利用しない。

---

## 18.9 クレジット消費・生成履歴の管理

### 18.9.1 管理目的

共通のクレジット管理原則は上位仕様に従い、Work方式ではCUT・区間・Take単位で記録する。

### 18.9.2 生成履歴の管理項目

| 項目 | 内容 |
|---|---|
| CUT | 番号・名称 |
| 区間 | T=0〜5秒等 |
| Take | 生成試行番号 |
| 使用モデル | 実際に採用したモデル |
| 生成方式 | Start / End等 |
| 入力素材 | 承認済み画像 |
| 生成尺・解像度 | 実際の生成条件 |
| プロンプト | 最終使用指示 |
| 想定・実消費クレジット | 生成前・生成後の値 |
| QA結果・採否 | OK / NG / 要確認、採用 / 不採用 / 保留 |
| 修正理由 | 再生成時の変更目的 |

### 18.9.3 生成コストの比較

一括生成と分割生成、中間静止画の有無、モデル別成功率、再生成回数、採用Takeまでの総クレジット、区間数と接続品質を比較する。コスト削減効果は実証まで確定事項としない。

### 18.9.4 生成開始前の承認

クレジット消費を伴う処理は制作者の明示的な承認後に限る。仕様確認・プロンプト修正を生成承認と解釈しない。

## 18.10 CapCut等への引継ぎ

### 18.10.1 引継ぎ条件

- [ ] 採用動画Take・CUT・区間が確定している
- [ ] 動画QAが完了している
- [ ] 重大なIdentity Driftが残っていない
- [ ] 衣装・特殊効果の重要変化が成立している
- [ ] 接続時刻と正式音源が確定している
- [ ] NG動画と採用動画が区別されている

### 18.10.2 引継ぎ対象

承認済み動画、CUT・区間、採用Take、接続時刻、正式音源、SE・テロップ指定、動画QA結果、編集上の注意事項。

### 18.10.3 最終編集

CUT接続、尺調整、音楽・効果音同期、テロップ・ロゴ、SNS向け冒頭演出、完成動画QAを行う。追加のAI生成は条件・想定クレジットを別途確認する。

9. 動画生成を実施していないのに動画完成と報告すること

11. 未検証のWork挙動を確定仕様として記載すること

# 第22章　総括

本仕様書が定義するWork方式は、開始時点と終了時点を確定し、その間の時間変化を中間静止画として設計・生成・検証する制作方式である。

従来の動画生成AI中心の制作に対して、時間軸上の重要な状態を制作者が個別に確認できることを特徴とする。

一方で、画像生成に成功したことは、時間方向の連続性や動画としての成立を保証しない。

したがって、本方式では次の原則を採用する。

> **Start / Endを固定する。**
>
> **時間軸を設計する。**
>
> **重要時刻を先に制作する。**
>
> **Identity・Geometryを維持する。**
>
> **全時刻の連続性を検査する。**
>
> **承認された画像だけを動画制作へ引き継ぐ。**

これを、竜宮プロトコルSNS動画制作におけるWork利用の基本制作原則とする。
